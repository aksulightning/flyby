# Minimal Alpine X11

This is a separate Disk Creator image based on Service Alpine. It runs Xorg with
software rendering, the twm window manager and xterm at 800 × 600. It does not
start a Wayland compositor or use XWayland.

1. Stop Linux and export your current disk if you want to keep its contents.
2. Open Settings → Disk Creator and select **Minimal Alpine X11**.
3. Create the disk, start Linux and open **Display**. Allow time for the first boot.
4. Tap inside xterm to focus it before typing. Use 512–768 MiB RAM.

Install RISC-V X11 applications with Alpine's `apk` command. Programs launched
from either Terminal or xterm inherit `DISPLAY=:0` and
`XAUTHORITY=/run/flyby-x11/Xauthority`. Only applications available for Alpine
riscv64 can run; this is not x86 application emulation. This image provides 2D X11 rendering; GPU acceleration and GLX are disabled.

For experimental OpenGL acceleration, choose the separate [Alpine X11 GPU](x11-gpu.md)
image and enable GPU in Settings.

The server accepts local Unix-socket connections with a fresh MIT-MAGIC-COOKIE-1
cookie on each service start. TCP listening is disabled. The image is a single-user
experimental root session, like the other Flyby images.

OpenRC starts `flyby-x11`, `flyby-x11-wm` and `flyby-x11-terminal`, using the shared
Flyby framebuffer/UHID input bridge. Logs are in `/var/log/Xorg.0.log` and
`/var/log/flyby-x11*.log`. A serial login remains available if the display fails.
The default keyboard layout is US, with right Alt as Compose.

The packages are pinned by version and SHA256 in `scripts/x11-packages.json` and
installed offline during image construction. The APK contains the compressed
`x11.seed`; first boot does not require a download. Only newly created disks use
this image. Updating the app does not replace or convert an existing disk.

`python3 scripts/test-x11.py` boots the real RV64 guest and checks the X server,
client environment, rendered framebuffer, keyboard input, batched input, pointer
and graceful shutdown. `FLYBY_CPUS=2 python3 scripts/test-x11.py` repeats these
checks with two online guest CPUs. Physical Android device testing is still needed.
